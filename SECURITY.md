# Security Policy

## Scope

This repository is the complete source of the public website
**https://aguocha.com**, a static site served by GitHub Pages. Everything in it
is public by design.

**In scope**

- `https://aguocha.com` and every route it serves
- The HTML, JavaScript, and CSS in this repository

**Out of scope** — please report these to the operator named below, who will
route them, rather than treating them as vulnerabilities in this repository:

- **GoHighLevel / LeadConnector** (`api.leadconnectorhq.com`,
  `link.msgsndr.com`) — the booking calendars and forms are embedded from a
  third-party platform. Issues in the platform itself belong to that vendor.
- **Spotify** (`open.spotify.com`) and **YouTube** (`www.youtube.com`) — embeds only.
- **`store.aguocha.com`** — a separate property, not built from this repository.
- Findings that require a compromised third-party CDN as a precondition. This
  risk is already documented and accepted; see `SECURITY-HARDENING-REPORT.md` §8.
- Missing `Content-Security-Policy`, `X-Frame-Options`, or `frame-ancestors`.
  GitHub Pages provides no mechanism to set custom response headers. This is a
  known and documented platform limitation, not an oversight; see
  `SECURITY-HARDENING-REPORT.md` §14.
- Reports generated by an automated scanner with no demonstrated impact.
- The public phone number being scrapeable. It is published deliberately.
- The GoHighLevel widget IDs, Spotify IDs, and YouTube IDs in the page source.
  These are **public embed identifiers, not credentials**, and cannot
  authenticate anything.

## Reporting a vulnerability

Please report privately first. Do not open a public issue, and do not open a
pull request that demonstrates the problem.

- **Text or call:** +1 (762) 248-6242
- **GitHub:** open a private security advisory on this repository
  (Security → Advisories → Report a vulnerability)

Please include what you found, the URL or file it affects, the steps to
reproduce it, and what an attacker could actually do with it.

We aim to acknowledge a report within seven days. This is a small independent
project, not a funded programme: there is **no bug bounty** and no payment is
offered.

## Testing rules

Because the booking calendars and submission form are live and reach a real
person, please:

- **Do not submit a booking or a form.** A test submission enters a real queue.
- **Do not send automated or high-volume traffic**, and do not run
  denial-of-service or brute-force tests.
- **Do not test the GoHighLevel, Spotify, or YouTube platforms** through this
  site, and do not touch other tenants on those shared services.
- Keep testing to your own browser against publicly reachable pages.

If demonstrating an issue would require breaking one of these rules, describe
what you would expect to happen and we will arrange a safe way to verify it.

## What is already known

Before reporting, please check `SECURITY-HARDENING-REPORT.md` in this
repository. It records the current assessment, including accepted risks,
platform limitations, and a list of explicit non-findings that have already been
investigated and ruled out.
